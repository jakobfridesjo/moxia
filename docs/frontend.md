# Frontend

## Structure

The frontend follows [Feature-Sliced Design](https://feature-sliced.design/) v2.1. `mise fsd` checks it.

```
app → pages → features → shared
```

- Import only from lower layers.
- Never import sideways between slices.
- `shared/` has no slices.
- No barrel files: import the concrete file via `@/`, with its extension.

```ts
import { useRadioManager } from "@/pages/radio/model/use-radio-manager.ts";
```

### Naming

| Kind      | Style                             | Example                |
| --------- | --------------------------------- | ---------------------- |
| Module    | kebab-case                        | `use-radio-manager.ts` |
| Component | PascalCase                        | `StationsManager.tsx`  |
| Route     | TanStack Router, in `app/routes/` | `_app/settings.tsx`    |

`/` is the radio, filling the window on its own. `_app/` is the pathless shell of the pages behind it: settings and about. Never edit `routeTree.gen.ts`.

### Page slices

- State and mutations: `model/use-<x>-manager.ts`
- Rendering only: `ui/<X>Manager.tsx`

`pages/radio` is the reference slice.

## Solid

The frontend is [Solid](https://docs.solidjs.com/) 2. `node_modules/solid-js/CHEATSHEET.md` lists what differs from Solid 1 and from React; these are the habits this code keeps to:

- A component runs once. What changes is read where it is used: in JSX, a `createMemo`, or an effect's first function. Never destructure `props`.
- A `model/use-<x>.ts` hook returns an object of getters (`get mode() { return mode(); }`), so `radio.mode` in JSX follows the radio; pass such objects on whole, and pass accessors (`() => value`) where a hook needs a value that changes.
- `createEffect(compute, apply)`: what `compute` reads decides when `apply` runs, and `apply` runs again whenever `compute` does, equal value or not. Read props and derived values through a `createMemo` there, or the effect repeats on every unrelated change. `apply` returns its cleanup. For work done once the component is on the page, `onSettled`.
- An element is kept with `ref={(element) => (box = element)}`; the short `ref={box}` hides the assignment from the linter.
- Solid Dev warns `STRICT_READ_UNTRACKED` in the console (and in test output) for a changing value read where it will not update. Fix the read; `untrack` only where once is meant.
- ARIA states are written `"true"` or `"false"` (`ariaBoolean` in `shared/lib/aria.ts`), attributes in lowercase (`maxlength`, `for`, `stroke-width`), and `class` takes a string, an array or an object.

## Calling Rust

- Every call goes through `commands` in `shared/api/commands.ts`. Never call `invoke` anywhere else.
- Show a failed command with `commandErrorMessage(error, fallback)`.
- Query options and keys live in `shared/api/queries.ts`. See [architecture.md](architecture.md#the-command-contract) for which settings belong in a key.
- Read a query with `useCommandQuery(options)` from the same file, not Solid Query's `useQuery`: its `data` is the plain value in the cache, undefined until fetched. `useQuery`'s own `data` holds its reader (and the page around it) back until the fetch lands, and is a store rather than the value Rust sent.
- A mutation updates or invalidates the queries it changes itself (see `pages/radio/model/use-presets.ts`).

## Player

- `features/player/model/player-store.ts` holds what plays in `playerAtom`. Rust reports through `play`'s channel, and `applyPlayerEvent` folds each `PlayerEvent` into the state.
- Start playback with `usePlayStation()`: it also refreshes the recent list.
- The player store also holds the recording and the tape in the deck (`deck`), which is what a recording plays back from. The tape's position is computed from when it started moving (`deckPosition`), so nothing ticks unless a component asks with `useNow`.
- `level` events go to `levelAtom`, not `playerAtom`, so nothing reactive follows them: the radio's painting reads it every frame.
- Anything that can end a recording bumps `tapesChangedAtom`; `useTapes()` refetches the tape list when it does.

## The radio

`pages/radio` is the whole main screen: an ink painting, drawn on canvas, whose inscription names the station. `ui/Inscription.tsx` writes the station as a painting's inscription (題款), in Chinese whatever the interface language and in the station's script (simplified for mainland stations, traditional elsewhere), and says only what nothing else on screen does. Columns read right to left from one top line: a carved seal of the region (中, 臺, 港 or 澳, 中 before a station is chosen) heads the station name, written as radio-browser lists it, frequency and all. The seal and the name's first column stand in the same place and the name at one size (`TITLE_REM`) for every station; a name taller than `TITLE_COLUMN_SVH` runs on into columns of even length to its left. Latin and numbers in it are set as vertical Chinese sets them (`inscribedRuns`: acronyms of up to four capitals and longer numbers upright in full-width letters, one or two digits across one square, words and phrases on their side, a size down and kept a quarter character clear of the characters around them, none broken across columns; brackets and other marks left out); and, while a recording plays, the lunar date at the stations, time of day and 錄 when it was made. There is no status seal: the listener listens or dozes, 录 is carved while recording, and the hint says the rest. The words live in `messages.radio.inscription`; `lib/inscription.ts` has the pure helpers. The programme shows in the hint line at the bottom as the station sends it, and errors, tuning, recording time and tape position there in the interface's language, and a screen-reader-only status carries the station and what is on.

- Each place is a leaf of an old ink painting, cut into ink by `mise art:ink` (`ui/ink/`; see [licences.md](licences.md#paintings)): three from Min Zhen's album of 1788 (Lu Tong reclining under his pine for the mainland, a boat in the reeds of a misty river for Taiwan, Su Dongpo, who lived out his exile up the coast at Huizhou, for Hong Kong) and, for Macau, Luo Ping's old scholar listening to a waterfall beside his boy. `LEAVES` in `lib/ink-painter.ts` says which leaf each place shows and which part of it moves: a head that nods about its neck, or the boat, which rocks and bobs. Leaves are measured in their own units (the layer's pixels at 1600 tall), cover the screen keeping their proportions, centred on the leaf's `focus` (the boat's leaf centres on the boat) as far as its edges allow, with their top edge fading into the paper. `paintScene` lays procedural paper and the leaf without its moving part; `drawListener` draws that part as `lib/mood.ts` poses it: turned about the neck by a pitch in units of the leaf's `turn` (1 lifts the chin as far as the cut allows; which way that turns follows `facing`), moved a few units the way it faces by its lean, and a scroll at the listener's hands while recording. `ui/ink/layers.ts` decodes each leaf once into an `ImageBitmap`; a place whose leaf will not load is bare paper.
- `ui/InkScene.tsx` holds the leaves on two canvases that take turns and animates the moving part on a third, posed each frame by `makeMover` (`lib/mood.ts`, pure and unit-tested). Only the figures' heads and mouths follow the sound; nothing else in the painting does, and no characters are drawn but the subtitles.
- Moods: there is no nodding to a beat. Each emotion SenseVoice tags a subtitle with (`MOODS`) is a rest pitch and lean for the speaker, a gesture kicked into the head on stressed syllables (the first after a pause, or one held long), a jaw gain and a spring (frequency and damping): happy lifts and bounces, sad sinks on a slow soft spring, angry chops down and leans in, fearful trembles, surprised jerks back with the jaw held open, disgusted recoils. A mood shows from `emotionSure` 0.35 and in full from 0.8, half as much in singing, blends in over 0.4 s and outlasts its line by 4 s. The one listening takes on part of it (`echo`), leans in or away, and nods at the speaker's phrase ends. The jaw opens on each character's time in `said`. Laughter bounces both heads, applause lifts the speaker and nods the other, crying drops the head, a cough jerks it. The `sound` event (`soundAtom`) sets the rest: talk over music gestures at 70%, singing sways the head once a phrase and lifts it on held notes, music lowers both heads to drift with the loudness averaged over 4 s, quiet leaves them breathing, and stopped dozes. The partner sleeps 15 s after the last words or song.
- Weather: `lib/ink-weather.ts` draws each painting's weather on top of the leaf, never moving or stretching it, in the layer's units: fog and mist from one tiling noise texture tinted paper and masked to soft bands, worked out on the GPU. What falls is cut out of the painting it falls from: the boxes at the top of the file are isolated marks in each layer (one needle stroke, one leaf, one cloud), copied once to their own canvases, which start at the angle they were painted, then turn and flutter down. Lu Tong: mist on the far slope, steam from the kettle, his pines' needles. The boat: faded copies of the two painted clouds drifting through the sky, the boat's reflection, river mist. Su Dongpo: paper mist scrolls up through a mask of his painted incense, so the brushwork itself seems to rise; catkins; mist at his feet. The scholar: the waterfall misting down the cliff (`lib/ink-falls.ts`: a soft veil over the painted sheet and on down behind the trees, with long faint streaks and finer threads of water down its middle pouring slowly, frayed edges, vapour drifting up through it, fading into mist at its foot; worked out per pixel by a shader), leaves from both trees, mist along the river and fog in the gorge. The scroll (`ui/MountainPath.tsx`, on a screen-sized 2D canvas just above the painting with the GPU's layer over it, both riding with the camera): cloud belts with parallax, the waterfall below the monastery, misting the same way, chimney smoke and temple incense, and mist on the river under the bridge. None of it follows the sound: it moves at its own steady pace while something plays. `lib/air.ts` tells it only whether anything plays (not while a dropped station is tried again, so the mist rolls in over it until it answers and the hint says it is trying again): `life`, which eases to 0 once nothing plays; then effect time runs at a quarter speed, nothing new falls, and a veil of mist rolls over the whole painting, figures and all. Reduced motion keeps the mist, held still, and drops everything else.
- Night (`lib/ink-night.ts`): the radio's ink is never inverted. Each place's leaf lies on a dark ground (`NIGHT_LOOK`: a moonlit gradient for the river and the waterfall, near black for the stove and the incense) and is lit by something in it: the fire under Lu Tong's kettle, flickering; the boat's lamp, swaying with the boat, with warm glimmers on the water beneath it; the ember of Su Dongpo's incense, warm on his face and hands and down his sleeves; and for the scholar a faintly glowing sky, moonbeams through the top branch (its leaves leave shadows down them), a sheen on the stream and the fall, and banks of fog from the figures' waists down. Light is drawn on the front canvas, then cut away wherever the leaf has ink (`behindInk`, against `Scene.ink`), so it seems to lie on the paper behind the strokes; the moving parts are drawn over it. Moonlight glints on the boat's river (and on the scholar's fall only soft gleams sliding down it; his stream has a sheen but no glints), each only where its whole streak lies on bare paper inside the water's outline, and no light follows the sound: flames flicker and water glints on the clock alone, steady whether anything plays. Soft edges are blurred by hand (`lib/soften.ts`), never with the canvas `filter`, which WebKit (the Linux and macOS webviews) lacks. `lib/ink-tone.ts` holds the colours laid over a painting (`Tone`): at night writing (subtitles) is pale and haloed in the dark, mist is moonlit but thin and blurred, since pale mist stands out on the dark far more than paper mist on paper (or firelit, or faint), smoke and steam are grey rather than ink (the painted incense, barely a wash, laid on thickly so it shows), falling leaves and needles are pale (both warm in the firelight, where night closes again over the mist and needles beyond the fire's reach), and what closes over the painting once nothing plays is dark. The mountain path at night is not inverted either: its ink stays black on paper dimmed by the moon (`PATH_NIGHT_SKY` down to `PATH_NIGHT_GROUND`), with its weather in `PATH_NIGHT_TONE`, its open sky moonlit (`MOONLIT_SKY`), lamplight in the huts, the village and the monastery's halls (`LIT_WINDOWS`), and a warm light glowing round the old man (see below), all as warm and faint as the boat's lamp by the river (`FIRELIGHT`).
- Day (`lib/ink-day.ts`): where the night has its lights, three places have a day of their own, each one shader over the whole screen (`InkGL.day`, compiled on first use) that only lays colour over the painting. The boat: soft, sparse rain in three depths slanting with the reeds, rings opening on the open river (kept out of the ink by `Scene.ink`) and an overcast sky. The scholar: sunbeams where the night's moonbeams come in, the rest shaded slightly so they read; the stream in ink and paper (a grey wash along its banks, whiter mid-stream, no ripple lines or glints; the same outline as the night's, never on the stone); light running down the fall with spray at its foot; and pale mist in the night's fog banks. Su Dongpo: the temple at noon, dim but for a shaft of sun from a high window through the smoke at his hands, fine dust falling and wandering through it (drawn in a second pass, `Day.over`, on the layer over the figures and only over the part of the screen the shaft can reach, so it falls in front of his head), and live incense smoke rising from the stick, thin, then wavering, then tearing into strands, grey in the shade and bright in the shaft. The painted wisp is left out of the leaf (`paintScene`'s `erased`) and the weather's smoke effect skipped (`liveSmoke`) while it rises. Reduced motion holds it still and drops rain, ripples, the fall's light and dust. The shaders skip their costly work (noise, polygon tests) outside the parts of the screen where it can show; their value noise is one filtered read of a 256-square lattice of hashes (`dayLattice`) rather than four hashes worked out per point, and the scholar's stream, stone and fall share one outline table, tested for inside before any distance is measured. Without a hardware GPU the day is as before.
- The real sky (`lib/sun.ts`, `lib/ink-sky.ts`, `model/use-local-sky.ts`): the painting follows the place of the station on show, at the coordinates radio-browser gives it, else for the mainland its province's capital (`lib/provinces.ts`, which knows pinyin, the old postal spellings such as Kiangsu, and Chinese names), else its region's main city (Beijing, Taipei, Hong Kong, Macau). The sun's height there, worked out each minute, decides day and night when the theme is auto (`placeNightAtom` in `shared/lib/night.ts`; once the radio is gone, auto follows the system again): night once it is 4° under the horizon, and the light of dawn and dusk warming the sky around the horizon. With weather on, `localWeatherQuery` asks Rust for Open-Meteo's weather there every half hour, as rain, snow, cloud, fog and wind from 0 to 1 and whether it thunders. One more shader over every painting, day and night (`SKY`, drawn after the figures so what falls passes in front of them), lays streaks of rain slanting with the wind, haloed snowflakes, fog banks, lightning and the dusk's warmth; a clear or merely cloudy day lays nothing, so the pass is skipped. The day shaders read the same weather (`u_weather`, `u_air`): the boat's rings open only while it rains and its clouds darken with the cloud, and the scholar's sunbeams and Su Dongpo's shaft fade under cloud and fog. Until the weather is known, or offline, each painting shows the weather it was painted with (`weatherFor`): soft rain on the boat's river, sun on the others. Wind blows through `ink-weather` too (`windOf`): from a calm to a gale, leaves, needles and catkins fall up to three times as often and are swept sideways, and mist drifts faster; it drifts by `blown`, effect time weighed by the wind and eased toward each new reading, so a change of wind never makes it jump. At night, how much moonlight comes through (`moonlight`: the moon's phase from `moonLit`, cloud and fog) scales Lu Tong's moonlight, the moon's glints on the boat's river (not the lamp's) and the scholar's moonbeams, sky glow, sheen and glints, while dark cloud drifts across the top of an overcast sky.
- Moving on: changing station blows a bank of soft fog across the painting the way the finger swiped (`gust` in `lib/ink-weather.ts`, two broad noise layers blurred until no cloud shapes show, one a little behind the other, three screen widths deep, 2.8 s), while the painting, its figures and everything cut from it wash out to the tone's paper by day, or fade into the dark by night, and back (`washOut` in `ui/InkScene.tsx`, laid over all but the fog and the captions). Changing place soaks the new leaf through the paper over the old from where the finger lifted (from low or high in the middle for the arrow keys), with a darker wet edge, over 2.2 s (`lib/ink-bloom.ts`: a mask about 48 cells across of distance plus noise, worked out each frame and drawn up smoothly in 2D, which costs three canvas passes a frame). The first painting, a resize and reduced motion crossfade instead. While one painting gives way to the next, the front stops drawing the figures: each frame both paintings redraw theirs into their own canvas, in the pose the front would draw (`figurePose`), so they fade or soak with their painting and nothing jumps when the front takes them back; at night the light is cut around those held figures too (`Moment.held`), as it is around the ink.
- On the GPU: what lies over the painting and is the same wherever it spreads (mist, the veil and the gust; the waterfalls; night light behind the ink, the dark over it and the scholar's moonbeams and fog; the day's and the sky's shaders) is drawn with WebGL2 by `lib/ink-gl.ts`. Each renderer draws on a canvas of its own that is shown as a layer, so nothing is copied between canvases: `ui/InkScene.tsx` stacks the two scene canvases, the layer under the figures (`InkLayers.under`: night light, mist, the waterfalls, the day), a 2D canvas for the figures, what falls and the night's glints, the layer over the figures (`InkLayers.over`: the sky, the veil, Hong Kong's dust, the dark, the gust and its wash) and the subtitles. Each frame starts with `clear`, draws are queued in order and land at `flush`; a frame drawn less often (`lib/ink-pace.ts`) leaves every layer as it was. Since what is cut from the painting is drawn in 2D over the under layer, the boat's low cloud and its reflection are drawn fainter to show as they did under the river mist, and the night's glints, drawn under the dark, are made brighter by as much (`lifted` in `lib/ink-night.ts`). `ui/MountainPath.tsx` puts one renderer's canvas over its 2D weather canvas. Light behind the ink is drawn into a texture of its own and then cut by `Scene.ink`, as `behindInk` does in 2D. Each place's night light is made once and kept by `ui/InkScene.tsx` while it is night (`nights`), and what it works out for the screen is kept for as long as the leaf lies the same on it, so coming back to a place does not build it again. `createInkGL` asks for a context with `failIfMajorPerformanceCaveat`, so where WebGL would run on the CPU (SwiftShader, llvmpipe) there is none, as with the shaders setting off (`shadersAtom`): none of it is drawn live, no weather, day light or bloom (a change of place fades instead), on the painting or the path; the night light is painted into the leaf once, held still, by the 2D code (`lightOnce`). While figures are held between paintings the night light is drawn in 2D, cut around them; once a context is lost its layer is left out. `lib/ink-gl.browser.test.ts` (with `allowSoftware`, since the test browser's WebGL runs on the CPU) checks which layer each effect lays on and compares the night on the layers with the 2D lighting pixel by pixel. Slow weather is drawn 30 times a second (`lib/ink-pace.ts`); a gust, a change of place and a moving camera on the path go at the screen's pace. The path's loop writes a style or attribute only when its value changes, so a still frame costs no style work.
- Moving parts are cut with hard-edged pixel masks when a leaf is painted (`mask`, `cutPiece`), so at rest each piece fits its hole exactly; smoothed edges on both sides would leave a pale seam through every stroke. Each frame `drawMoved` lays a piece over its own resting ink, minus the shape the moved piece covers, so a turning head or opening jaw uncovers the strokes that were there, never bare paper.
- Talk: `lib/talk.ts` tells talk from music by the player's levels, about twenty a second. Speech dips between syllables several times a second; music, even quiet, holds its level. Over the last six seconds of sound, 1.6 dips (of about 5 dB) a second or more is talk and under 0.9 is music; silence, as a stream starts, does not count. A station tagged as news, talk or the spoken word (`isTalkStation`) starts out talking and needs fewer dips to stay so, since heavily compressed talk barely dips. With subtitles on, the speech models say instead when the listener talks and what plays; without them, `makeMover` takes talk from here, works the listener's `jaw` to the voice (dropping it shows the dark of the mouth) and treats everything else that plays as music. Talk wakes a leaf's `partner` (Lu Tong's servant lifts his head); having no jaw, his chin dips with each syllable. The thresholds come from 40 s samples of CNR-1 and Shanghai news against pop and classical stations. The listener follows the leaf on show, not the place just picked. Reduced motion holds it still.
- Subtitles: the 字 seal (under 设) turns them on or off with `setSubtitles` (`features/player/model/subtitles.ts`), or sends the listener to settings while the speech models are not downloaded; the setting is `subtitlesAtom`, and they come back on at start once the models are there. Settings' subtitles card also picks the characters they are written in (`subtitleScriptAtom`: 简体, or 繁體 in Taiwan's or Hong Kong's forms, sent with every `setSubtitles`, so a change while they are on applies at once), whatever the interface language, and the readings written small beside each character (`subtitleReadingAtom`: none, pinyin or zhuyin, sent the same way). `subtitle` events go to `captionsAtom`, which the painting reads every frame like the levels. `lib/captions.ts` splits each into cells: Chinese a character to a cell, anything else a word to a cell; each fades in over 0.4 s as it is said (the event's `said`), the caption stays 3.5 s and fades, or gives way in half a second once the next thing is said. `captionWriter` writes it in a box `ui/InkScene.tsx` measures from the screen (`captionRoom`): as far from the screen's left edge as the top seals are, that far below them and one line of writing more (`CAPTION_LINE`), and that far short of the usual inscription (`INSCRIPTION_ROOM`: the seal's column and a little more; a name in two columns comes closer, so the box is the same for every station), down to `CAPTION_END` of the screen's height, the same on every painting, as is the size of the writing (set in units of the screen's height, not the leaf's, so a leaf drawn larger to cover the screen does not enlarge it): from the box's top-left corner, filling each line across the box before moving down to the next (`wrap`; no line starts with a closing mark), starting again at the top once the box is full; haloed in paper. Each page of a caption has its glyphs written once onto a canvas of its own, then copied cell by cell each frame at the cell's ink (each cell's part tiles the page). Halos spread past their cell, so each cell's halo is drawn once on its own, whole, faded in with the cell, and laid down on the page's halo canvas once the cell has all its ink; every halo is drawn under every glyph. A page is written again when the box, the tone or the loaded fonts change. Subtitles have a canvas of their own, touched only while there are any. Readings, pinyin or zhuyin, sit above each character at nearly half its size, each character spaced so its own reading fits. While subtitles are on, the listener talks while a subtitle is being said; his partner only listens.
- By day, behind the inscription the paper is cleared by a ragged mist grown out of the writing itself (an SVG filter on the inscription spreads its strokes into one wash per column, tears and feathers the edge, so it follows the columns however they wrap and fades into the brushwork), and the hint glows with paper, so the painting never runs under writing.
- The app is portrait: the desktop window opens 430×860 and Android locks the activity to portrait.
- The keys are seals (`ui/Seal.tsx`): settings in the top left corner, in a block two seals wide: settings and the mountain path of recordings (山), then subtitles (字) and listening together (同); the presets bottom left, recording (a round seal) bottom right, with the category seal (`ui/CategorySeal.tsx`) midway between the two while the radio plays: 全 printed for every station, or a category's character carved (乐, 闻, 谈, 路, 综). A press turns it to the next and the hint names it and counts its stations; the categories either side wait as faint bare characters, and a press on one goes straight to it. A seal is an upright, worn stamp: `SealMark` draws its outline and character in SVG, printed through the filters `SealInk` mounts once per screen (`lib/seal-ink.ts` picks one of eight stones by the character). Each blurs the shape, adds fine grit and cuts it back to a hard edge, so corners and stroke ends round off and edges chip; the red gets a faint mottle, the character a much lighter wear so it stays legible. The ink multiplies into the painting, over a paper wash in its own layer, feathered past the seal's edge (`seal-wash`) so it sits on cleared paper rather than a tile, that keeps the character readable on busy brushwork; at night there is no wash, as red reads on the dark as it is. Off, a seal is red lines (朱文); on, solid red with the character cut out (白文), so the painting shows through it.
- The six presets are one seal cut into a 3 × 2 block (`ui/PresetBlock.tsx`), each cell a key over the print: each cell is its formal numeral (壹貳參肆伍陸, 贰叁陆 in simplified), printed in full on a stored key and half translucent on an empty one, and carved on the key on air. A key plays on a press and stores the station on air when held (`model/use-hold.ts`), the cell filling with red from the bottom meanwhile; a press that moves becomes a drag and does neither, but one the button slips out from under (as a gliding slip does) still counts.
- The recordings stand along a path up Chen Chun's hanging scroll _Looking for a Monastery in the Misty Mountains_ (`ui/MountainPath.tsx`), a screen of its own over the painting that the 山 seal opens and its pressed twin, or Escape, closes; it opens with the scroll unrolling from its roller. The painting is the `monastery-path` ink layer, 2.3 screens wide, and `lib/scroll-path.ts` measures the path in its pixels: a smooth curve through hand-placed waypoints from the man on the bridge, up past the huts, the village, the ledges, the monastery and the waterfall to the peak. The waypoints keep to land, never across the river or up the falling water; check any change against the painting. Each recording is a paper slip tied to a stone on the path, the newest just above the bridge and each older one a slot further up toward the peak (`slotAt`): 24 reach the peak, and past that they close up. When a recording is made the others glide up to make room. Slips alternate sides counted from the oldest, so a new one leaves the rest where they stood. The path opens at the bottom, on the bridge. The camera follows the path, not the page: dragging anywhere, slips included, pulls the painting along it (down to climb, sideways where it winds) and flings on when let go; so do the wheel, the arrow keys, Page Up and Down, Home and End. A finger resting on the painting holds it still, so a slip never slides out from under a tap. Focusing a slip by keyboard brings it into view, since the screen is `overflow-clip` and never scrolls. The old man always starts on his bridge, turned from the painting to face up the path. He is cut from the painting by `mise art:ink`, his body and his dark cane apart (`travellerPart`; `ui/ink/traveller-body.webp` and `traveller-cane.webp`), and once he leaves, his strokes on the bridge are masked out of the painting (`traveller-hole.webp`), so the paper behind shows there as everywhere else, lit or not. He walks to whichever recording plays at an old man's pace, rocking with each stride as his cane swings, and stops as near its stone as he can without a slip hiding him, just beside its edge, coming from wherever he was; he faces the way he walks and keeps facing it when he stops, and a paper clearing behind him keeps him visible against the foliage. He walks behind the slips, never in front of them. A tap plays a recording without leaving the path, and tapping it again pauses or resumes it. Recordings play only here: rolling up the scroll takes the recording out and the radio plays the station it was on when the path opened. Holding one sends the old man to it: the slip trembles while he walks there, he slowly raises his cane and brings it down, and the slip cracks into pieces (with a crack, when key sounds are on) and stops if it was playing. The pieces fade away over five seconds, and tapping them mends the slip. Once they have faded, or as soon as the scroll is rolled up, even before the cane lands, the recording is deleted. At night a warm light glows round him and barely wavers: a radial `Firelight` (the houses' lamplight and the sky's `Moonlight` are laid the same way) on the paper under the painting's ink layer, so the paper glows and the ink stays as it is, as with the boat's lamp; a colour-dodge over the painting was tried and turned the grey washes red. The paper clearing behind him is lit to match. Holding a slip at night, he bends to it instead of raising his cane, and it catches fire and burns away from the bottom up behind a charred, ragged edge with flames along it (`BurningSlip`: a mask moved by the `--burn` custom property; with a rush of flame and crackling, when key sounds are on), its light flaring on the paper round it and dying to embers. Tapping the embers within the same five seconds brings it back, unburning.
- Listening together: the 同 seal (beside 字) opens a hanging scroll (`ui/TogetherSheet.tsx`) where the listener picks a name (`listenerNameAtom`) and opens a room (邀, invite) or pastes an invite to join one (赴). In a room it shows the invite as a QR code (`ui/InviteQr.tsx`) and text to copy, how many are listening, and 散 to leave. `model/room-store.ts` holds the room in `roomAtom`; `applyRoomEvent` folds each `RoomEvent` in. `model/use-listen-together.ts` keeps it in step with the player: it plays whatever someone else tunes to (`follow`), tells the room each station this listener tunes to once it follows the room (`shareStation`, which skips the station the room already has, so following never echoes back), and puts arrivals, departures and changes of station in the hint corner. While in a room the 同 seal is carved with the count beside it, the last three messages drift over the painting above the presets for 45 s (`ui/ChatDrift.tsx`), and a 言 seal beside 录 opens the conversation (`ui/RoomChat.tsx`) over the lower part of the painting, with a line to write in and 寄 to send. Each message with Chinese in it has a 譯 Translate button that toggles its English beneath it (`model/use-message-translation.ts`, through `translationQuery`, which keeps each translation for good); while the translator is not downloaded, the message offers the download in its place and translates once it arrives. Both sheets sit outside `main`, so its taps and its `touch-none` never reach them; Escape closes them. The QR code is always black on white, so a camera reads it at night too. On a phone (`canScan`), 赴 also offers to scan an invite: `camera.scanQrCode` in `commands.ts` asks for the camera and runs Tauri's barcode scanner plugin (mobile only; `capabilities/mobile.json`) in its windowed mode, where the camera lies under a see-through webview. Meanwhile `.scanning` on the root hides the whole page but `ui/ScanFrame.tsx`, a frame to aim with and Cancel; the scanned invite is joined at once if there is a name, else it waits in the paste field.
- A tap on the painting stops or plays; a sideways swipe, or left and right, seeks through `dialOrder` (country, then region, then name), or through the recordings while one plays. Seeking keeps to the category chosen (`categoryAtom`: every station, or music, news, talk, traffic or full service, which Rust reads into each station's `categories`): `seekStation` goes on from wherever the dial is to the nearest station in it, so picking a category changes nothing until the next seek, and a change of place goes to the next country with such stations. A swipe up or down, or up and down, jumps to the first station of the next or previous country (`nextCountry`), and so to its painting.
- Station favicons are remote and often `http:`; if one is ever shown, load it through Rust's `get_favicon`, never in an `<img>` directly.

## Text and settings

- **UI text** lives in `shared/i18n/messages-{en,sv,zh-hans,zh-hant}.ts`. Never hard-code a user-facing string. Chinese is two interface languages, `zh-Hans` and `zh-Hant` (Taiwan usage: 設定, 下載, 電臺); they share what is Chinese whatever the interface language, except that the traditional radicals replace the simplified ones (訁 for 讠).
  - English defines the `Messages` type; the others must match it.
  - Read it with `useMessages()`, whose sections follow the language where they are read (`m.common.back` in JSX), or `currentMessages()` outside a component (e.g. the player store).
- **Numbers and dates** follow the language through `appLocale()`.
- **Chinese text** gets `lang="zh"`, so the webview shapes it as Chinese.
- **Settings** are persisted atoms (`shared/lib/atom.ts`) in `shared/config/preferences.ts`. An atom is a signal: a component reads it by calling it (`themeAtom()`) in JSX, a memo or an effect. A signal shows a write only after Solid's next flush, so code outside the components, which reads what it has just written, uses `get`, `set` and `subscribe`. The weather setting (`environmentAtom`) stops the ambient weather and the day's light on the painting and the path; the night's lights, the veil over silence and the gust on a station change stay. Turning shaders off turns all of them off, except the night's lights, which then hold still, and greys out the weather setting.
- **Model downloads** run through `shared/api/model-downloads.ts`, whose atom keeps each download's progress outside the components, so it carries on while the listener goes back to the radio. Settings' subtitles card downloads, cancels and deletes the speech models, and turns subtitles on once they arrive; the translation card does the same for the translator. Both use `ModelSection` and `useModelSettings` (`pages/settings`).

## UI components

### Primitives

`shared/ui/shadcn/` holds the primitives, in shadcn's look and naming: buttons, cards, inputs, and those that need behaviour (tooltip, menu, slider, collapsible, toggle group) on [Kobalte](https://kobalte.dev/), toasts on `solid-sonner`.

- They are written by hand: shadcn has no Solid components, so never run `shadcn add`. The `scroll-fade` utility is copied from shadcn's stylesheet into `app/styles/shadcn/`.
- Each takes only what the app uses. Add a part, or a new primitive, when something needs it; knip deletes what nothing imports.
- Kobalte marks state with `data-expanded`, `data-closed`, `data-pressed`, `data-disabled` and `data-orientation`.

### Other components

Everything in `shared/ui/` outside `shadcn/`: flat, as PascalCase files with named exports. Icons are Lucide's, drawn with `Icon` (`shared/ui/Icon.tsx`) from the `lucide` package: `<Icon icon={ArrowLeft} />`.

### Ink look

- `globals.css` defines `paper`, `ink`, `ink-soft` and `seal`, and builds shadcn's tokens from them (paper surfaces, ink text and washes, seal-red primary, near-square corners). Headings and `font-brush` are calligraphy. Settings and About sit on the same paper as the painting (`app/layouts/AppLayout.tsx`).
- Day and night: settings' `themeAtom` is auto, day or night; `nightAtom` (`shared/lib/night.ts`) resolves auto by the sun where the station on show is while the radio shows (see "The real sky"), else by the system's colour scheme, and `main.tsx` sets `.dark` on the root, which turns the four tokens to dark paper and pale ink (so `dark:` utilities apply). Seals stop multiplying into the paper at night (`dark:mix-blend-normal`), since red multiplied into dark paper would vanish. Neither the seals nor the inscription have a wash at night: red and pale writing read on the dark as they are.
- Chinese text is calligraphy everywhere: LXGW WenKai (`lxgw-wenkai-webfont`) follows the Latin fonts in `font-sans` and `font-serif`, and leads `font-brush`. LXGW WenKai TC (`@fontsource/lxgw-wenkai-tc`) fills in traditional characters it lacks. Both are bundled and split by glyph range, so the webview loads only the slices a screen uses. Only WOFF2 ships: `vite.config.ts` drops the WOFF copies fontsource also lists.
- `Seal` clacks like a mahjong tile when the key sounds setting is on (`shared/lib/key-sound.ts`): a filtered noise strike with a few short inharmonic partials, then a softer settling knock, pitched a little differently each press. Web Audio, no sound files.

### Styling

- Reach for shadcn variants and sizes (`size="xs"`, `size="sm"`, `variant="outline"`) before `class`.
- `class` is for layout, not restyling.

### Surfaces

| On the page canvas | Use                             |
| ------------------ | ------------------------------- |
| A panel            | `Card` (`size="sm"` when dense) |
| A long list        | Straight on the page, no frame  |
| An alert           | `Alert`                         |

- Inside a card or dialog, boxes are flat: `rounded-lg border`, no shadow.
- An `overflow-*` container holding cards needs `-m-1 p-1`, or it clips their ring and shadow.
- Cards in a scrolling flex column need `shrink-0`. `Card` is `overflow-hidden`, so it would shrink instead of scroll.

### Overlays

Follow the Apple and GNOME HIG:

| Situation                    | Use                                                              |
| ---------------------------- | ---------------------------------------------------------------- |
| Managing one record's list   | A routed page: `PageHeader onBack`, primary action in the header |
| Options before one action    | A plain `Dialog`, `sm` or `md`                                   |
| Opening over another overlay | Only an `AlertDialog`                                            |

Dialog footers:

- A bare `DialogFooter` or `AlertDialogFooter` takes no padding: the content already pads it.
- With two buttons, give it `grid grid-cols-2 sm:flex`, Cancel first, so the buttons sit side by side on a phone.
